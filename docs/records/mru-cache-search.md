# MRU lookup in bounded plan and shaper caches — shodo-sbp.13

Both caches previously searched the oldest entry first, then moved each hit to the newest end. Each now searches with VecDeque::iter().rposition. The returned index still refers to the original forward order; remove/push_back/pop_front and entry capacities stay unchanged. The plan remains qualified by the full FontId and the unchanged harfrust key (script, direction, language, feature-variation selectors, ordered feature tag/value/global-range equivalence). Shaper entries remain face-index qualified inside their already selected font layer; shared/document delegation is unchanged. No capacity increase, word cache, public API, dependency or default-limit change is introduced. Saved spikes and the original diagnosis artifacts are untouched; performance never blocks raikiri switching or S4.

An independent Python list model derives every cache order, hit/miss/eviction and visited-entry count for each request, including hits after promotion and misses after capacity churn. Plan operations include FontRef/shaper-view construction; shaper operations include the existing mutex and handle clone. Thus times measure complete lookup operations, not isolated comparison instructions. Cold fill retains new cache data; warm scopes compare changes from an already populated cache. Clear-to-zero-capacity is validated outside scope.
