# Bounded `ch` / `ic` unit cache measurement

`shodo-6hd` retains the exact `FontUnit` produced by the existing single-character shaping path. A hit uses the full `FontQuery`, validated font size, and unit character (`0` or `水`); the per-layer cache is cleared when either the shared or document font generation changes. It retains at most `min(match_cache_entries, 64)` entries per layer, skips keys exceeding 128 families or 4,096 bytes of family/language text, and is disabled when `match_cache_entries` is zero. Shape work occurs outside the layer lock. The value is inserted only if the observed generations did not change during shaping. The uncached shape path and its 1/64 px rounding remain the source of values.

The comparison uses the exact post-PR-#87 binary from the [original cost record](ch-unit-cost.md), built from commit `35eda9ee7b4bd816041822aede2c913046d0ac05`, and a new binary from optimization commit `cd204193cd79436e20398536a0f2b02534d95196` on main merge `fa3411acecfd5aad20a14338cc3936706552370d`. Both use the same `ch_cost` source SHA-256 `d38beec6f07f1215cfafe62249a2e0c42bc4532c237647e0331379a4afb372c1`, committed `Cargo.lock`, Latin/CJK fixture bytes, Rust 1.96.0, release opt level, AMD Ryzen 5 5600G and Linux CPU 0 affinity. The prior binary SHA values match the original record. The intervening main changes include no change to this unit measurement path; the optimized commit changes the font-unit cache and its tests.

The fixed 96-span, 800 px workload performs 288 `resolve_ch` and 96 `resolve_ic` calls per document. Each process has 32 warmups. Time uses 12 independent process pairs in alternating order, each with 21 samples of 8 repetitions. Allocation uses 5 independent pairs and 21 single-operation samples, with separately built allocation-counting binaries. Process medians and paired cached/post-#87 ratios are below. Allocation counts are requested allocator operations in the warm measured scopes, not RSS. The raw process samples, summary, and manifest with hashes retain the complete evidence. The raw gzip SHA-256 is `64ef2fa5fc28bf62983221e7fed67d1a48442cb6a83e74371ea0a5f51ab7f257`.

Both builds produced 20 lines and the same 14,892.046875 px sum of line inline widths in every measurement. The fixed-font exact-fit and intermediate HVAR regression tests compare cached and uncached values with exact `FontUnit` equality, including the selected face. Additional tests cover `ic`, query fields, sizes, fallback and generic changes, shared/document registrations, zero and bounded capacity, concurrent registration, and poisoned-lock recovery. This deliberately ch-heavy synthetic caller is evidence of this unit path's cost, not a WPT or real raikiri throughput result. The saved S4 spikes were not modified.
