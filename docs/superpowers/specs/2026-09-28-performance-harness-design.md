# Standalone reproducible performance measurement design 

Issue shodo-p2m.8. Purpose: measure standalone shodo runtime and actual allocator bytes, separate cold font/context initialization from warm build/layout and paragraph reuse, retain reproducible inputs and machine/build metadata. No raikiri production switch (.6 excluded), no S4 merge, no raster work in measured scopes. Architectural subsystem, native inline execution under existing autonomous goal. Base635269db13d45e9d8a391fb7cf2cb854363e81e4; branchfeat/performance-harness at/tmp/shodo-benchmark. User-authorized autonomous native execution; this spec is not represented as human-reviewed.

Compare approaches: (1) Criterion wall time plus separate allocator/cold process probe (selected): retains foundation §6.4 Criterion intent, distribution/raw/baseline support, avoids instrumentation contaminating timing. (2) custom all-purpose runner: fewer dependencies but must reimplement statistics and adaptive batching. (3) Criterion custom allocator Measurement: combines metadata but allocator interception remains present in timing and process-cold ownership is unclear. Pin available Criterion0.7.0 (Rust floor1.80, project floor1.89) with default features disabled and cargo_bench_support only.

New dev/bench workspace package publish=false, root default members still root. Shared runtime workload module consumes fixture fonts/corpus, owns build preparation, line/source/glyph digest and public retries. Criterion benchmark consumes it; measurement binary handles process-cold and allocation checkpoints. Python orchestration records exact revision/dirty/source hashes/toolchain/CPU/OS/build flags/features/font/input bytes and hashes, calls tools by argv, stores all raw outputs and validated comparisons. Comparison must refuse incompatible conditions and missing workload/checksum evidence. Timing instrumentation off; allocator feature separate binary invocation. All preparation/JSON/metadata IO outside clock and counter scopes. Results are paired by workload/operation/scale, never summarized as whole-page raikiri speedups.

Workloads cover fixed12cases at1/8/64 repeats, Latin/CJK/Arabic/combining/mixed, RichText and ParagraphBuilder, many short paragraphs, inline nesting/atomic, preserve tabs/spaces, float retry and justify. Corpus scale separated from paragraph count. Operations: warm build, first next_line, all lines, intrinsic, width sequence reuse vs rebuild, height rejection/next-page same-token retries. Cold process child parses fixed manifest before clock then initializes FontCollection/LayoutContext, registers fixed faces and builds/lines with CJK font-layer data untouched; process launch/loader time reported separately by parent, not included in engine inner time. Prewarming marked explicitly for warm measurements.

Memory global allocator wrapper compiled only with allocation-counting feature, delegates to System. Atomic counts for successful alloc/alloc_zeroed/realloc bytes, deallocated bytes, global live and scope high-water. Realloc success adjusts live by delta and counts requested new size as gross allocation, old size as freed; failure leaves live unchanged. Sample begins at current live baseline, counter deltas measure only chosen work. Peak additional=max(scope peak-start live,0); retained net is signed (previous owners may be released). Snapshot counts do not allocate. Single-threaded probe with exclusive nonnested scope and no output while active. Explicit checkpoints fonts/context/paragraph/all Line/justified Line/dropped Lines/dropped paragraph/shrink0/dropped fonts distinguish shared retained font/context ownership from outputs. Per-glyph/per-line ratios have valid nonzero denominators and named ownership scopes. Allocator excludes stack/mmap/native allocator overhead/RSS, so no process-memory claim. Time samples from this binary are not used for regressions.

CI normal tests smoke workload/digest/protocol and allocator accounting plus Python schema/comparison. Manual performance workflow runs release fixed short measurement and uploads metadata/raw files without runner-noisy percentage failure. Local complete measurement records real results and same-machine repeat comparison. Criterion raw baselines, frozen package lock/build configuration and metadata are preserved in output dir; avoid overwriting output on invalid configuration/run failure. Expected limitation: subset fonts fixed representative content, synthetic fallback must be counted/diagnosed, not called fullUnicode coverage. Current real shaper, previous docs debug sample retained as historical.

Sources verified read-only: foundation§6.4; issue full description; Criterion official timing_loops (iter includes Drop, batched excludes setup/output drops and bounds batches), command_line_options (save/compare baseline; cargo test --benches smoke). Rust GlobalAlloc contracts verified: delegated successful realloc transfers ownership; failure preserves the old allocation. No allocations, locks, unwinding or formatting within allocator callbacks. All .15 integration/cleanup prerequisites and .8 claim/worktree completed; baseline must finish before code changes.


Exact initial matrix: all12 original corpus IDs at scales1/8/64 with a single RichText span; many-short-latin at paragraph counts1/8/64 using latin-short unchanged; nested-atomic, preserved-tabs, float-retry and justify variants using latin-short at repeats1/8/64. Fallback variant uses mixed-scripts with only Latin named first and pinned CJK/Arabic fallback. No system font lookup. Fixed widths come from each case; width-change sequence is base,base/2,base*1.5. Page retry uses max_block_size0 to force rejection, retries the unchanged token at a page width, and verifies rejected calls do not consume text. Float retry supplies two fixed literal widths and a float cursor before resuming, retaining the number of reports and retries in digest evidence. It measures shodo's public call protocol, not a full CSS BFC. Atomics use literal20x20 with baseline16; nesting depth4 and end padding2. All source settings, operations and requested scale are serializable into fingerprints.

Criterion operations build, next_line, all_lines, intrinsic, reuse_widths, rebuild_widths, page_retry. Layout operations prebuild and prewarm outside timing. build includes builder/RichText input insertion and processing, excludes construction of benchmark-owned source strings/style configuration; output drops excluded via bounded LargeInput batches. Rebuild operation includes builder and layout. Baseline digest uses source ranges, dimensions, glyph IDs/clusters/positions, stable fixed-face identity, actual run and line counts, report/retry counts. It must not include paragraph ID or process-local FontId. Digests are captured separately from clocks/counters and must agree for equivalent reuse/rebuild and cold/warm inputs. An operation error aborts measurement; no shorter output can silently be recorded as faster.

Memory reports use common workloads, counts at initialization, registered fonts, built paragraph/context, plain lines, justified lines, rejected/retried pages, width reuse/rebuild and final releases. Per-glyph bytes are retained paragraph/context increment per painted glyph (not internal store struct size); per-Line is additional retained line ownership per retained Line; justify delta compares independently owned plain/justified line outputs against the same warmed paragraph/context baseline. Shared context changes are reported explicitly. Build+drop memory scopes and retained-output scopes are separate. No division by zero. Gross bytes are successful requested bytes; deallocation bytes and signed net together identify allocator churn and reuse. If optimized allocations disappear, report measured calls without asserting source-level allocation guarantees.

Reproducibility: release opt-level3, debug0, incrementalfalse, fixed features complex-scripts enabled/web/system disabled for package-selected invocation. Record exact cargo/rustc verbose info, target/profile/env flags, resolved Cargo.lock SHA and copy, package source/input/settings/font SHA256, OS/architecture/CPU, tool configuration and raw durations/Criterion estimates/samples. Comparison requires exact workload/operation/fingerprint, toolchain/host/build conditions, matching output digest and successful scopes. Revision differs intentionally. A missing case, empty sample, nonfinite/negative duration, malformed counter, hash difference or mismatch fails clearly before output replacement. No statistical speedup claim from a single cold sample; include all cold samples, median and sample count; report process wall separately. CLI validates sample bounds and selected cases before build/output writes; publish into a new directory only after successful runs, preserve earlier results on failure.

Output fixtures stored in dev/bench/results/initial.json only if fully provenance-qualified and small, full raw artifacts externally archived; never a strict wall-time golden. Tests can inject command runner for process failure while validation tests execute real schema/comparison and actual probe. Tests of allocator delegate use explicit raw allocations with hand-derived sizes to avoid relying on optimizer-preserved Box allocations. Allocation feature is compiled only for probe and its dedicated accounting test binary, never Criterion timing.
