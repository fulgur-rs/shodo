# Paint styles design

Issue shodo-ods. Deliver resolved text color, underline and strike-through from ParagraphBuilder/RichText to immutable accepted output without separating ligatures or joining. Caller rasterizes; DOM is optional. Architectural API change, native execution under the user's autonomous issue/PR/CI/merge instruction. This document is self-reviewed, not represented as human-reviewed. Base 5eb1ac7f895f887cc8f24e8291a730b0d62cb34b. The raikiri spike and shodo-p2m.6 remain excluded.

## Alternatives and chosen boundary

1. Node-only painter lookup cannot express DOM-independent retained paint information and repeats the existing gap.
2. Arbitrary generic Brush carried through every builder/output forces a generic rewrite across public geometry and ownership APIs.
3. A resolved non-premultiplied sRGB RGBA8 PaintStyle embedded in InlineStyle (selected) satisfies the required color alternative without dependencies or breaking existing Line ownership. Existing NodeId remains available for caller effects beyond solid color.

## Input and glyph ownership

Public style::PaintStyle has color: [u8;4] (default opaque black), underline: Option<TextDecoration>, strikethrough: Option<TextDecoration> (default none). TextDecoration has color: Option<[u8;4]>, offset: Option<f32>, thickness: Option<f32>. None color uses this source style's color; None offset/thickness uses the actual font instance metrics. Some offset is signed px toward line-under from the alphabetic baseline (or central baseline for upright text); thickness is nonnegative px, zero paints nothing. Inputs clamp to finite +/-1e7 px; nonfinite optional lengths fall back to None with existing warnings; negative thickness becomes zero. Paint never affects layout metrics/advances, intrinsic widths or shape compatibility.

InlineStyle.paint carries the values. GlyphRunView::paint_style returns the retained paint owner's style for the accepted normal/first-line dataset. A shared cluster is painted once with its first scalar's source style, even across colors. Font fallback changes font metrics, not paint ownership. Color-font palettes remain separate. Paint is added to the supported first-line property subset, including caller-resolved per-inline alternatives and legacy equal-value inheritance; shaping/whitespace properties remain as before.

## Source spans and resolved decoration output

Line::paint_spans() -> Vec<PaintSpan<'_>> returns source-owned text intervals with node, processed UTF-8 text_range, retained style, final logical rect, actual font/font_size/metrics. The rect uses container-relative inline and block coordinates including Line.block_offset, like selection_rects. It includes final bidi order, tabs, preserved whitespace, soft-hyphen output and justification. Collapsed nonpainting space and atomic replacement characters produce no text paint spans. Span intervals are intersections of source items with the finalized selectable grapheme segments; ligature subranges use the existing GDEF/proportional caret geometry. Indivisible graphemes/transforms shared across sources can have coincident rectangles: source coverage remains explicit without inventing a forbidden caret. Spans are ordered by processed source position, not physical coordinate. No per-scalar reshaping or duplicate glyphs.

PaintSpan::underline()/strikethrough() -> Option<DecorationRect> resolves color and metrics and returns a logical rectangle centered on baseline+offset, with thickness across the perpendicular axis. Horizontal/sideways text decorates along inline; vertical-lr reverses line-under in the logical block direction. Upright text uses the central baseline and the declared metric-based policy, not a claim to CSS auto/left/right heuristics. Combined text decorates along its internal horizontal block axis with its scaled source widths and accepted composition alphabetic baseline in the inline axis. Run metrics come from the actual fallback/variable/font-size-adjust instance; tabs use the primary resolved style metrics and their containing box shift. Decorations can overflow the line; they do not affect line height or Line::ink_bounds.

Reuse the existing hit index's source segments through a crate-private bridge rather than duplicating GDEF caret algorithms. A call builds an index; callers retain the returned spans for repeated painting. Use ordered interval lookup for item/run metadata to avoid scanning the entire paragraph per span. Do not modify hit/selection behavior.

## Caller responsibilities

Inputs are resolved per-source paint, not CSS cascade/decorating-box propagation. The caller computes inherited color and propagated decorations; disabling a child here disables its resolved decoration. Multiple overlapping ancestor decorations, overline, wavy/dashed/double strokes, text-underline-position heuristics, skip-ink, text shadows and color-font rasterization remain painter responsibilities. Geometric source spans are not a full CSS decorating-box implementation; line-edge whitespace clipping and padding/atomic bridging require caller policy. The example demonstrates solid strokes only, never claims WPT parity. Pixel conversion uses the accepted Line writing_mode/used_direction with PhysicalConverter; physical rounding, clipping and antialiasing are caller choices.
