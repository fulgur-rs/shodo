# Completed height retry design

Issue shodo-c91.4; base 7d771b4ed5c954150300f62a314a4f14098879ab. The user authorizes sequential isolated implementation, PR, passing CI, merge and owned cleanup for all six children.

Retain one owned completed Line only after a genuine height rejection. Repeat rejection compares exact needed height; acceptance moves the Line and removes the entry. Ordinary acceptance retains nothing. Box the private entry so ordinary context size adds one pointer. No public API or default limit changes.

The key covers retained paragraph Arc identity, complete token, built/live font generations, sanitized width/inline/block offsets, all LineOptions, max_graphemes, exact float cursor, atomics generation and global revision. Immutable paragraph ownership covers styles, limits and source. Bypass break plans, alternate first-line cursor datasets, annotation lanes and explicit selected ends. Clear incompatible entries before early invalid/done/block events. Always sanitize inputs, reset the per-line reshape budget and execute the height gate. A clean unsuppressed warning checkpoint before sanitization and after completion plus clean saturation and no build warnings is required. Resource fallback or new warning prevents retention or hits.

Charge at most 64KiB for entry/key/header and actual owned capacities: every Line Vec, boxed slice, GlyphStore vector, pending overlay/run and recursive Ruby base_nodes/child heap. Embedded child Line headers are already in Ruby record capacity. Shared paragraph/font/run instance owners extend lifetime separately and are not deep cloned; measure release explicitly. Capacity arithmetic fails closed, recursion is bounded. Explicit context shrink drops the completed entry.

Alternatives: Arc<Line> requires cloning to return owned output; retaining height alone rebuilds geometry at acceptance. An owned rejected Line is the initial candidate; retain the old implementation if output equivalence, actual work reduction and whole operation allocation/time/retention do not justify it.

Validation uses real fixed fonts, actual Line constructor counts and zero real clones; literal needed/source bounds; fresh full recursive output, ordered warnings and complete non-Line event sequences. Keys, atomics revision, live font generation, first-line/plan/floats/forced/block, max graphemes, saturation, warning suppression, resource budgets, oversize, shrink, owner lifetime and returned output independence are required controls. Separate counter-free timing and allocator/actual-work observers, pin six producer builds, complete checks first, then balanced A/B. Record gross/freed/net/whole peak and owner extension, all adverse timings and conditional decision. Preserve originals/saved worktrees; no switching blocks.

Context dependency refinement: public builder and intrinsic operations invalidate the completed entry before work/error returns because they can replace edge/shaping caches and affect resource fallback. Plans call public next_line and consume/invalidate entries before other line work. take_warnings preserves entries but eligibility observes suppression before every retry. No caller can mutate private caches directly. Actual disabled-font-cache controls construct FontCollection with that limit, with only ephemeral FontId layer identity normalized; registered face index and fixed font bytes remain exact.

Measured retention refinement: the unrestricted grapheme-limited trial retains1,236B of geometry while prolonging15,606,476B of shared paragraph/font storage in the repeat2048 control (probe Vec backing excluded; weak Arc block/context release separate). Retain only when PartialLine already owns the exact paragraph/token; max_graphemes, tabs/unsafe raw scans and other nonretained trials stay on the original path. This avoids extending root paragraph/font lifetime beyond the existing raw owner. Check build warnings recursively on selected Line/annotation paragraph owners after the64KiB capacity guard; a child's run-byte fallback can exist with a clean root and empty layout warning sink. Shared run-instance metadata remains separate from the owned geometry cap. Both refinements have real RED regressions before implementation.
