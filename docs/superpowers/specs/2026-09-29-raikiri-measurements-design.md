# raikiri native / candidate measurement design

Issue `shodo-8ei` extends the existing measurement foundation. Native inline execution is authorized by the persistent issue-development goal; this document is not represented as human-reviewed. Neither preserved S4 branch is modified, pushed, or merged. `shodo-p2m.6` remains excluded.

The original acceptance remains intact: the same pinned WPT input, fonts, environment and viewport; initial layout, changed widths and page retries on native and candidate; cold/warm repetitions; durations and requested allocated/peak/retained bytes; isolated engine and complete caller boundaries; exact inputs, revisions and commands; unsupported/failed cases excluded; observed regressions assessed and tracked. Partial tooling or geometry validation does not close this issue.

Use a disposable archive of S4v2 `fe67a281210fbc52d22032911ac3584405aa8198`, with its original ignored Cargo.lock recorded separately. The probe uses that candidate's actual shodo version, not a silently substituted main checkout. All source transformations require exact source SHA and unique anchor matches. Main receives the measurement recipe, probe and report, never S4 implementation commits or copied upstream algorithms. The recipe captures and preserves the supplied checkout HEAD/status/diff and ignored lock during extraction. If another task advances or dirties that checkout, source is read from the exact immutable S4v2 commit via git show/archive; working source is never borrowed or reset. The ignored lock must retain its original pinned SHA.

Approaches considered: directly time public page painting (rejected: mixes raster and layout); recreate a new complete CSS caller (rejected: changes the candidate being measured); expose the preserved candidate's existing layout pass in a disposable archive (selected). The generated entry point removes image allocation, snapshot serialization and paint calls, retaining sizing, projection, accepted lines, source checks, natural block height and margins. It returns the same block geometry. Validate every previously supported page (121 at 800×600) against the original recorded block geometry, resources, warnings and font registry before using this boundary. The removed paint checks remain represented by the original page support classification; the layout entry point is not a broader supported-page claim.

Allocation counting uses the existing allocator in a separate build. Timing binaries have no counting allocator. Parse/cascade, font initialization, isolated preparation/layout, complete caller layout and output release have distinct ownership scopes. No raster work or result serialization is inside layout scopes. Retained-byte results name their owners: a native laid-out DOM, candidate block output, retained standalone shapes or accepted lines are different ownership sets and must not be conflated. Peak requested heap bytes are not RSS.

Measured caller inputs that are consumed and freed must be allocated in that same window: the native `FontContext` clone is counted inside its caller. Shared configured font caches survive page-output release. Records therefore distinguish page/prepared-owner release from final registry release; common `WptFonts` setup contains both registries and the original font byte copies, and is not an engine-specific layout cost. Isolated geometry preconditioning and its output release are separate scopes. Current real allocator evidence balances every measured owner across all 121 documents for both engines, apart from explicit native single-threading-bound exclusions.

The pinned native DOM exposes text layouts immutably. Actual native text preparation first creates fresh shapes in `relayout_text_for_width`; mutable retained-layout copies needed by width/retry APIs are made in a separately named setup scope. They never stand in for initial shaping. Native preparation retains 224 text layouts outside the candidate's compared leaf roots across this inventory. Initial text-pipeline costs include this difference and DOM cloning; reused-width/retry costs operate on paired leaf roots with the same content widths. A pure per-run native shaping comparison is not inferred from these broader preparation costs.

Initial and width-change complete-caller measurements use the actual preserved algorithms. In particular native re-entrance reshapes text; the candidate public whole-page function also rebuilds paragraphs. Isolated width reuse separately retains shapes. An isolated first-shape sample cannot be obtained by cloning already-shaped output. An isolated common-input comparison must retain original DOM/source/style provenance and reject features it cannot represent, rather than remove CSS. Native Parley and candidate shodo retries use actual public breaker state/token restoration and verify rejected trials consume no source. Complete-caller pagination needs real flow output and is classified unavailable whenever the preserved caller cannot represent the input or fragmentation semantics; successful comparison rows require their declared operation to complete, never fabricated page retries.

Results retain raw samples, exact operation/boundary, cold/warm state, prewarming, width sequence, fragment constraints, accepted source/output digests, font/resource SHA, pinned commits, resolved lock, toolchain/profile/flags, host metadata and exact argv. A partial result is useful evidence but not full acceptance. Ratios compare like boundaries only; changed or missing output, incompatible input, instrumented timings, missing scopes and failed processes cannot be summarized as speedups. Regression followups include a minimal reproduction, measurement uncertainty and a reasoned switching-necessity decision.

For the remaining paged boundary, expose the frozen static caller's existing CSS preflight and used width/edges separately from shaping. The disposable `candidate_page_inputs` helper borrows the exact guarded original prefix through the construction of each `MeasuredBlock`; no new CSS sizing implementation is introduced. Its roots, content widths and edges must match the validated static caller on all121 original documents. A separately labelled provisional page-flow consumer can then compose those inputs with the already preserved public `FlowDriver::paginate`, carrying real page cursor/checkpoints, source and widow/orphan limits between represented leaf blocks. It is distinct from the original static wrapper. Native uses the actual pinned `layout_pages`/fragment producer. Fragment constraints and source partitions are validated before like-operation cost comparisons; unsupported edges, margins, page styles or native/candidate fragmentation differences stay explicit. Calling the static helper with a smaller height is never labelled pagination.

The standalone initial-library observation uses a second disposable archive,
separate from the whole-caller binaries. SHA-guarded observers bracket the real
candidate `ParagraphBuilder::build` and the native sequential job's actual
Parley `ranged_builder`, default-style API calls and `build`. Original library
and caller algorithms remain unchanged. Preparation resumes after each observed
call, including initial line breaking; observer metadata and source hashing are
outside every window. Dispatch overhead at the boundaries remains included and
explicit. Both modes reject native inputs with 32 or more original text nodes
because this observer is confined to the verified sequential branch.

Each sample creates fresh shapes and retains the actual prepared owners until
their separately measured release. Candidate raw builder text and native
caller-processed job strings keep their own byte lengths and digests; library
APIs and input granularity differ, so these are per-engine construction costs,
not a fabricated common-input glyph-shaping ratio. Full source/glyph snapshots
must equal the independently collected isolated initial output on the original
input. Preparation, all observed library windows, owner release, original input
geometry and final configured font/cache release must balance in memory mode.
