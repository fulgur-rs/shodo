# Accessibility output and optional AccessKit integration

Issue shodo-1bn. Expose accepted paragraph text, selectable characters, source positions, attributes and geometry to assistive technology. Editing buffers and IME are not prerequisites. Base ca3c7e1b055280d84c3bb239a5e86d0cd6a3482f (PR24); clean build/workspace baseline671/0 across51binaries. This design is self-reviewed under the user's autonomous issue/implementation/PR/CI-success merge instruction; it is not represented as human-reviewed. The raikiri spike and shodo-p2m.6 remain outside this work.

## Approach

Documenting only existing glyph/hit getters leaves each caller to invent logical reading order and selectable units. Exporting glyph fragments directly to AccessKit duplicates shared glyphs, misorders bidi text and couples the core to one backend. Choose an always-available, backend-independent `accessibility::AccessibleLayout` borrowing accepted Lines, plus an optional `accesskit` feature exporting a real AccessKit tree and position adapter. Reuse the existing hit index; do not reshape, rasterize, change caret cuts or create an editor.

## Core public contract

`AccessibleLayout::new(lines: &[Line]) -> AccessibleLayout<'_>` borrows accepted lines and builds one `hit::LineLayout`. An automatically assigned nonzero snapshot ID separates positions from different exports, including reflow of the same Paragraph. No font or paragraph data is duplicated. Accepted Lines retain the data after layout owners drop.

`lines() -> &[AccessibleLine<'_>]` returns supplied line order. `logical_text() -> String` concatenates each accepted line's own covered processed text without inserting soft-wrap separators. This is processed source text, not glyph reconstruction: preserved hard breaks, tabs, soft hyphens and formatting controls retain their source representation. Each line retains its own dataset; never index a first-line slice into the normal paragraph text.

`AccessibleLine` exposes `index`, `text: &str`, dataset-relative `text_range: Range<u32>`, `characters: Vec<AccessibleCharacter<'_>>`, `runs: Vec<AccessibleRun<'_>>`, `writing_mode`, `direction`, `break_reason` and container-relative logical `bounds`. An empty accepted line remains a line with one empty run and a character boundary at its start; an empty supplied slice has no positions.

An accessible character is an interval between adjacent distinct accepted caret offsets, not a glyph or Unicode scalar. `AccessibleCharacter` exposes `text`, `text_range`, `kind: AccessibleCharacterKind` (`Text`, `HardBreak`, `Atomic(NodeId)`), `rect`, `leading` and `trailing` logical points. Thus an ffi ligature can have three GDEF-based characters, while a combining/ZWJ/indivisible transform has one character. Geometry reuses the cached hit segments; nonpainting gaps have caret-derived zero extent instead of disappearing. Every byte of the accepted covered text belongs to exactly one character. Leading/trailing points follow accepted caret geometry and support TCY's internal axis.

`AccessibleRun` exposes `character_range: Range<usize>`, `text_range`, `node: Option<NodeId>`, `style: &InlineStyle`, `font: Option<FontId>`, `font_size`, `bidi_level`, `orientation` and `bounds`. Consecutive characters within a line share a run only when their source owner, resolved attributes, actual font instance, orientation and bidi level match. Atomics and hard breaks remain identifiable. A character crossing source/style boundaries is indivisible and uses its first text scalar's attributes; source conversion still follows the accepted OffsetMapping. Actual fallback/SHY font information comes from accepted glyph output; tabs use primary resolved style information. Empty/nonpainting output may have no actual glyph font.

`AccessiblePosition { snapshot: u64, line: usize, character: usize, affinity: Affinity }` addresses a boundary in a line's character array, including its end. `AccessibleSelection { anchor, focus }` preserves selection direction. `SourcePosition { origin: TextOrigin, affinity: Affinity }` retains caller source identity and boundary side.

Methods: `snapshot_id() -> u64`; `position(line, character, affinity) -> Option<AccessiblePosition>`; `to_text_position(position) -> Option<hit::TextPosition>`; `from_text_position(hit::TextPosition) -> Option<AccessiblePosition>`; `to_source(position) -> Option<SourcePosition>`; `from_source(SourcePosition) -> Vec<AccessiblePosition>`; `selection_rects(AccessibleSelection) -> Vec<LogicalRect>`; `hit_test(inline, block) -> Option<AccessiblePosition>`.

Conversions normalize through existing caret affinity/snapping. Invalid indices, foreign snapshot IDs and out-of-range offsets return None/empty; NaN hit coordinates return None. Source mappings are not bijections after collapsing/expansion, and generated content has identity without a DOM byte offset. Inverse results are explicitly one-to-many, in supplied line order, deduplicated. With offset mapping disabled, text/geometry still work but original-source conversion returns no result. Preserve source anchors before reflow and resolve them against the new snapshot; old line/character positions are rejected, not silently reused.

## Optional AccessKit adapter

Pin `accesskit = 0.24.1`, optional, default features off; matching development consumer0.38.0. The inspected crate's Rust floor1.85 fits shodo MSRV1.89. Root default/no-default dependencies remain free of AccessKit and platform backends. Consumer tests live in the fixture crate behind its `accesskit` feature. No OS accessibility adapter, focus manager or event loop enters the core.

`accessibility::accesskit::AccessKitAdapter::new(root: accesskit::NodeId) -> Self` stores a persistent registry and current position tables. `update(&mut self, layout: &AccessibleLayout, root_node: accesskit::Node, frame: PhysicalRect, selection: Option<AccessibleSelection>, semantics: impl Fn(NodeId) -> NodeSemantics, allocate_id: impl FnMut() -> accesskit::NodeId) -> Result<accesskit::TreeUpdate, AccessKitError>` builds a complete root/children update. `to_position(AccessiblePosition) -> Option<accesskit::TextPosition>` and `from_position(accesskit::TextPosition, Affinity) -> Option<AccessiblePosition>` use only the latest successful export.

The caller chooses the root role, semantics, focus and globally disjoint ID allocation. The example uses a read-only Document root, which the real consumer supports for text ranges. `NodeSemantics { role: accesskit::Role, label: Option<String>, description: Option<String> }` defaults to GenericContainer/no label/no description; atomic alternative text comes from this callback. Text-source wrappers can carry caller DOM roles without reconstructing a DOM tree; default text semantics need no wrapper. The caller allocator must return fresh IDs; reject collisions with the root and current/new exported nodes. Stable keys use original DOM source-start identity where available, otherwise generated identity plus processed start, with occurrence disambiguation for repeated identical anchors. Do not include line number in a DOM key. Removed keys leave the active map and their positions are rejected. Updating source content requires caller source identity/selection reconciliation, not an editing subsystem. The emitted tree is a standalone read-only document with focus on its root; embedding into a host tree requires the caller to supply host root/parent/focus/tree metadata.

Children are in logical reading order. TextRun nodes split at attributes, line, direction, atomic semantics and at most255 selectable characters. Character byte lengths use complete selectable units, never scalar approximations. Same-line next/previous links follow reading order. The caller frame supplies finite nonnegative dimensions and origin; use each accepted line's writing mode/direction with PhysicalConverter. Character bounds, directional positions/widths, fallback font size, language, font weight/style and retained solid paint attributes are exported. Derive physical text direction from accepted leading/trailing points, including bidi, vertical and TCY axes.

An atomic semantic wrapper has a TextRun child whose value is its supplied alternative (or U+FFFC when absent), counted as one selectable unit and mapped to the atomic's before/after source boundaries. Its wrapper role/label/description remain caller-defined. A hard-break character exports LF for the AccessKit newline convention; soft wraps add no newline. Normalize a hard-line-end caret to the break's beginning when exporting selection, while range selection across the break reaches the next line. This normalization is explicit; generic source byte positions remain available in the core.

AccessKit's per-character length is u8. A selectable unit or atomic alternative above255 UTF-8 bytes cannot be exported faithfully: return `AccessKitError::CharacterTooLong` before changing registry/position state. Long descriptions can remain separate semantic descriptions. Invalid frames, source selections or duplicate IDs also return errors without replacing the previous successful export. Do not truncate text, split an indivisible unit or publish a partial tree. Core data has no AccessKit byte-length restriction.

## Responsibilities and verification

shodo provides retained text units, geometry, attributes and position conversion. Callers provide atomic alternatives, DOM meanings, tree embedding/global IDs, focus, action dispatch, platform registration and event delivery. An actual consumer example validates text ranges, character geometry, selection conversion and tree updates without an editor or IME. It is not a claim of end-to-end screen-reader/platform certification.

Task1 implements core output, all source/position conversions and empty/bidi/ligature/emoji/whitespace/transform/first-line/vertical tests. Task2 implements optional AccessKit, consumer-backed text/selection/geometry, atomics, identity/reflow and failure atomicity tests. Task3 adds the reproducible read-only integration example, public contract docs, feature-specific CI and full stable/MSRV/wasm/fixture gates. Preserve existing snapshots. One fresh whole-branch reviewer at the end, one verified Important/Critical fix pass, then authorized exact-head CI merge/issue close/owned cleanup.

Review focus: first-line and normal datasets with different UTF-8 lengths; nonpainting hard breaks/controls and empty lines; style/source boundaries inside an indivisible grapheme; stale positions and removed node IDs after reflow; units above255 bytes and failed exports preserving the previous adapter state. Each is pinned by a named task test.
